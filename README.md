# MeshPilot

Локальная консоль обслуживания CachyOS. **Этап 2: разовые измерения CPU, RAM, места на `/`, трафика по интерфейсам и времени работы, только чтение.** Есть CLI и окно Tauri v2 с Dashboard на Svelte и TypeScript. Нет работающего помощника, изменений DNS, очистки, установки пакетов, фоновых служб или синхронизации. При открытии приложения согласие не предполагается.

`meshpilot status` отвечает, что уже известно. `meshpilot doctor` читает ID системы и проверяет наличие системных утилит по фиксированным путям, **не запускает** их. На Live ISO с `ID=arch` дополнительно сверяются название системы и маркер CachyOS; JSON сохраняет исходный `os_id`. Наличие файла не доказывает работоспособность сервиса. В окне `—` и «нет данных» означают отсутствие измерений; это не нулевая нагрузка, не отсутствие обновлений и не отказ сети. «Быстрая очистка» открывает предварительный экран без удаления. `meshpilot ready` относится к готовности интерфейса.

### Что показывает CPU

`meshpilot status` и карточка «Загрузка CPU» показывают среднюю нагрузку по всем CPU, видимым ядру. Адаптер без root дважды читает первую строку `cpu` из `/proc/stat` с паузой 500 мс. Рядом с процентом — **фактический** интервал по монотонным часам, источник и время окончания в UTC. В JSON v1 поле `cpu` содержит `usage_percent`, `busy_ticks`, `total_ticks`, `interval_ms`, `source`, `observed_at_utc`. Разности тиков позволяют проверить, из чего получился процент; это не частота процессора и не `load average`.

Суммируются разности от `user` до `steal`; `idle` и `iowait` не входят в занятое время, `guest` и `guest_nice` повторно не прибавляются. Дельта нулевого общего времени, регрессия счётчика, неполная строка или недостоверный интервал → `cpu: null` и «нет данных». Если тики прошли только в простое, это **измеренные 0 %**. В нативном окне замер запускается при открытии и по кнопке «Обновить замер CPU», без блокировки интерфейса и независимо от RAM. Нагрузка по ядрам и история не собираются.

### Что показывает RAM

`meshpilot status --json` возвращает поле `ram`: `used_bytes`, `total_bytes`, `source` и `observed_at_utc` (UTC, RFC 3339). Источник `/proc/meminfo`: занято = `MemTotal − MemAvailable`; `kB` ядра = 1024 байта. Это память, видимая ядру, а не RSS MeshPilot и не лимит контейнера. В текстовом отчёте — байты, в карточке — двоичные единицы с округлением до двух знаков.

Окно запрашивает один снимок при открытии; кнопка «Обновить снимок RAM» запрашивает новый. Карточка и нижняя строка используют один ответ. Каждый отдельный вызов CLI снимает новое показание, поэтому объём занятой памяти может отличаться. При ошибке источника `ram: null`, в CLI и Dashboard — «нет данных». В браузерном предпросмотре нет нативного источника. Фонового опроса, истории за 60 секунд и сохранения замеров нет.

### Сколько места доступно на `/`

`meshpilot status` показывает три числа в байтах: **занято**, **всего** и **доступно обычному пользователю**. Адаптер вызывает `statvfs("/")` один раз. Заняты все несвободные блоки; в доступное входят только блоки `f_bavail`. Не всякое свободное место доступно пользователю: `всего − занято` может быть больше этой величины. Это файловая система, содержащая `/` для процесса (на Live ISO это может быть overlay), а не ёмкость физического накопителя, сумма разделов или гарантия успешной записи.

В JSON v1 `root_fs` содержит `used_bytes`, `total_bytes`, `available_bytes`, `source: "statvfs(/)"` и `observed_at_utc`. В Dashboard карточка «Занято на /» и панель «Корневая файловая система» показывают **один снимок** в двоичных единицах. Нативная кнопка «Обновить снимок ФС /» обновляет оба представления, не перезапрашивая RAM или CPU. Если чтение не удалось, результат — `null`, а не 0 байт; старые значения и время убираются. Измеренные 0 байт остаются нулём. Каталоги не сканируются, очистка не запускается.

### Приём и передача по интерфейсам

`meshpilot status` показывает среднюю скорость в **байтах в секунду** для каждого интерфейса из `/proc/net/dev`. Например, `lo` помечен как локальная петля: это не скорость интернета. Значения физических и виртуальных интерфейсов не суммируются. В JSON v1 поле `network_io` содержит фактический интервал, источник, UTC и пары дельт/скоростей по именам. Неподвижные счётчики дают `0 Б/с`; исчезнувший интерфейс отсутствует, а у нового или сбросившего счётчики скорость неизвестна. `online` и `dns` не определяются по трафику.

CPU и сеть в CLI **делят одну паузу 500 мс**. Для сети — два ограниченных чтения, не по паре файлов для каждого интерфейса. Карточка «Трафик сети» и нижняя строка показывают один выбранный интерфейс. Переключение использует уже полученный снимок; «Обновить замер сети» получает новую пару. Нет таймера опроса, истории, сетевых запросов или новой зависимости. [Контракт и пределы](docs/ARCHITECTURE.md#реализовано-трафик-по-интерфейсам).

### Как долго работает система

`meshpilot status` показывает время работы ядра из одного чтения `/proc/uptime`: целые секунды с момента загрузки, источник и UTC. В JSON v1 поле `uptime` содержит `uptime_seconds`, `source` и `observed_at_utc`. В панели «Среда» это строка «Время работы» с источником и временем; кнопка «Обновить время работы» запрашивает новое чтение. Секундного таймера нет, поэтому значение обновляется только по запросу, а не каждую секунду. Это не время до перезагрузки и не длительность сессии пользователя. При ошибке чтения `uptime: null` и «нет данных», а не 0 с. Измеренные 0 с после свежей загрузки допустимы. [Контракт](docs/ARCHITECTURE.md#реализовано-время-работы-системы).

## Запуск без установки

```sh
cargo run --locked -p meshpilot-cli -- status
cargo run --locked -p meshpilot-cli -- doctor --json --dry-run
cd apps/desktop
npm ci
npm run tauri -- dev
```

Нужны Rust stable (версия для CI в `rust-toolchain.toml`), Node.js 22.22.3 и для нативного окна — GTK 3, WebKitGTK 4.1, компоновщик, pkg-config и графическая сессия Linux. Для просмотра в браузере достаточно `npm ci` и `npm run dev` в `apps/desktop`. Шрифты и иконки локальные. В [приёмке на CachyOS Live](docs/VM-SMOKE.md) окно открылось в x86-64 Plasma редакции Handheld 260628 со штатным WebKitGTK. На Desktop 260809 CLI работает, но двух библиотек для окна нет; приложение их не устанавливает. Терминал нужен для разработки, не для действий в будущем GUI.

CLI: `0` — отчёт построен; `2` — ошибка аргументов или неподдерживаемая команда; `3` — `doctor` не подтвердил обязательную предпосылку. Отчёт при коде `3` всё равно доступен. На подтверждённой CachyOS `doctor` также показывает, есть ли в `/usr/lib` файлы WebKitGTK 4.1 и JavaScriptCoreGTK 4.1 для окна. Это проверка путей, а не загрузки библиотек. Их отсутствие, как и отсутствие необязательного Flatpak, не блокирует CLI и само по себе не ведёт к `3`. `--json` выдаёт схему 1; `--dry-run` допустим, обе команды и без него только читают. `updates apply` и прочие действия следующих этапов не имитируются.

## Дерево и границы этапа

```text
Cargo.toml, Cargo.lock, rust-toolchain.toml
crates/
  meshpilot-core/       сейчас: модели отчёта, Plan, JobBook, чистые переходы
  meshpilot-linux/      сейчас: пассивная диагностика Linux, CPU, RAM, корневая ФС, RX/TX и время работы
  meshpilot-cli/        сейчас: бинарник meshpilot и интеграционные тесты
  meshpilot-net/        позже: DNS и проверки доступности (2)
  meshpilot-agent/      позже: агент пользователя, Tokio, IPC, события (2)
  meshpilot-helper/     позже: узкий сервис с Polkit (3)
  meshpilot-sync/       позже: AEAD, ревизии и Dropbox App Folder (6)
apps/
  desktop/              сейчас: Vite, Svelte, TypeScript, lockfile npm
    src/                main.ts, App.svelte, компоненты, тёмная тема
    src-tauri/          независимый манифест приложения и lockfile; не CLI
    tests/              браузерная приёмка собранного интерфейса
  android/              позже: Kotlin и общее Rust-ядро (7)
tests/                  сейчас: инварианты проекта, smoke-тест окна в VM
.github/workflows/      сейчас: проверки workspace и desktop
packaging/              позже: PKGBUILD для meshpilot (6)
docs/                   дорожная карта, контракты, решения, контрольная точка
```

Пути с пометкой «позже» не созданы и не включены в Cargo. `meshpilot-core` ничего не знает о GUI, pacman, systemd, Android или Dropbox. Манифест desktop отделён, чтобы CLI на сервере не требовал GTK и даже разрешения его зависимостей.

## Проверки из корня

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
cargo build --workspace --locked
cargo package -p meshpilot-core --locked
python3 tests/project.py
npm --prefix apps/desktop ci
npm --prefix apps/desktop run check
npm --prefix apps/desktop run build
CHROMIUM_BINARY="$(command -v google-chrome)" npm --prefix apps/desktop run test:layout
cargo fmt --manifest-path apps/desktop/src-tauri/Cargo.toml --check
```

На Linux VM с нативными библиотеками дополнительно:

```sh
cd apps/desktop
cargo clippy --manifest-path src-tauri/Cargo.toml --locked --all-targets -- -D warnings
npm run tauri -- build --debug --no-bundle --ci -- --locked
xvfb-run -a dbus-run-session -- bash ../../tests/native-window.sh src-tauri/target/debug/meshpilot-desktop
```

[Приёмка в CachyOS Live](docs/VM-SMOKE.md) проверяет CLI и нативное окно внутри отдельной VM без NIC и пишущего диска. CI не меняет сеть хоста и не публикует артефакты. Проверка Cargo-пакета ядра — не сборка PKGBUILD и не релиз. Результаты, а не только список команд: [контрольная точка](docs/STATE.md). Полный объём и способы проверки: [требования 01–100](docs/ROADMAP.md).
