# MeshPilot · архитектура и IPC

**Что действительно есть:** [дерево со статусами](../README.md#дерево-и-границы-этапа), CLI, пассивный Linux-адаптер, чистая модель задания, окно с четырьмя пустыми карточками. Остальное ниже — **предложенный контракт**, не API работающего привилегированного сервиса. [Переходы и восстановление](STATE-MACHINES.md) · [бэкап v1](BACKUP.md) · [проверки](STATE.md).

## Процессы и границы доверия

```text
Сейчас, пользователь Linux
  CLI meshpilot → meshpilot-linux → чтение os-release/маркера CachyOS и метаданных утилит/библиотек окна
  Svelte → WebView Tauri → только собственное окно (drag/minimize/maximize/close)
  meshpilot-core: модели и правила, не делает I/O

Предложено, этапы 2–6
  CLI ──────────┐
  Desktop/Tauri ├─ Session D-Bus ─ meshpilot-agent.service (UID пользователя, Tokio)
  Tray ─────────┘                    ├─ meshpilot-core: правила, план, отчёт
                                    ├─ meshpilot-net/linux: проверки без root
      недоверенные новости/профили → ├─ ограниченный импорт как данных
      облако, только App Folder  ↔   ├─ meshpilot-sync: AEAD, ревизии, локальная очередь
                                    │
                    граница прав    └─ System D-Bus: тип действия + ссылка на план
                                          ↓ UID отправителя, Polkit, повторная валидация
                                     meshpilot-helper.service (root, allowlist)
                                       ├─ управляющий соединением / менеджер пакетов
                                       └─ защищённый журнал + независимый таймер отката

Позже, Android: Kotlin UI и системные согласия → общие модели Rust и sync
                 VpnService / Keystore / установщик остаются на стороне Android
```

Окно не запускает shell. Нет HTTP API для управления системой. Полученный по IPC `JobId` — ссылка, не полномочие. Agent и процессы одного UID не являются границей безопасности друг для друга. Helper не читает пользовательский журнал как доказательство согласия: восстанавливает **свой** канонический план по доверенным системным данным, проверяет субъект вызова и авторизацию. Конфигурации VPN, тексты новостей, сеть, облако и весь WebView недоверенны. Не передавать helper шаблоны команд, пути для перезаписи, окружение, аргументы менеджера пакетов или имена произвольных служб. Сборка AUR, подписки, уведомления, GUI и Dropbox не работают от root.

### Размещение и владение (пока ничего не создаётся)

| Данные | Владелец и путь | Правило |
|---|---|---|
| Конфигурация | пользователь, `~/.config/meshpilot/` | Версия, схема, атомарная замена, последняя рабочая версия; при повреждении только диагностика |
| Задания, события, обезличенные логи | пользователь, `~/.local/state/meshpilot/` | Режимы 0700/0600; изменения фазы и курсор событий в одной транзакции |
| Данные, зашифрованные бэкапы | пользователь, `~/.local/share/meshpilot/` | Секреты отдельно, не экспортировать ключи туннелей и OAuth |
| Доказательство плана и изменений | root, `/var/lib/meshpilot/` | Каталог root-only, доверенные дескрипторы, не следовать пользовательским ссылкам |
| Планирование | `meshpilot-agent.service`, `meshpilot-helper.service`, `meshpilot-*.timer` | Пользовательская служба не получает системные права. Таймер отката — системный, вне agent |

Первые три пути — значения по умолчанию XDG. Для root не использовать переменные окружения вызывающего клиента. В журнале: причина, стадия, код результата, длительность; по умолчанию без DNS-истории, профилей с секретами и полного stdout сторонних программ.

## Модель этапа 1

[Исходный Rust](../crates/meshpilot-core/src/jobs.rs) — источник истины. Сокращённая сигнатура типов (без атрибутов сериализации):

```rust
pub struct JobId(pub u64);
pub struct PlanId(pub u64);
pub struct Plan { pub id: PlanId, pub steps: Vec<PlanStep> }
pub struct PlanStep {
    pub operation: Operation,
    pub reason: String,
    pub authority: Authority,
    pub reversible: bool,
    pub on_failure: OnFailure,
}
pub enum Operation { Diagnose, TrialDns, UpgradeOfficial, UpgradeUserFlatpak }
pub enum Outcome { Succeeded, Partial, Failed }
pub enum JobPhase { AwaitingConsent, Ready, Running, Critical, Finished(Outcome), Cancelled }
```

`JobBook::register` не выполняет план. Одинаковый `PlanId` и то же содержание → прежний `JobId`; другое содержание → `PlanChanged`, пустой план → `EmptyPlan`. `JobPhase::transition` нельзя заставить начать работу до `Approve` или отмениться в `Critical`. Это проверено в памяти, не тест долговечности будущего журнала. ID на JSON-границе — десятичные строки (без потери точности JavaScript), в D-Bus допустим `uint64`. При реальном IPC UID, установка и ревизия плана привязываются сервером; счётчики должны сохраняться и не переиспользоваться после падения.

## IPC v1 — предложено

Имя на соответствующей шине **`io.github.Knox1986X.MeshPilot`**, объект `/io/github/Knox1986X/MeshPilot`, версионированный интерфейс `io.github.Knox1986X.MeshPilot.V1`. Одинаковое имя на двух разных шинах не означает одинаковые полномочия. Клиент проверяет `protocolVersion`, `capabilities` и `epoch` через `Hello`. Неизвестный major, действие или поле входного плана — отказ **до** любого эффекта.

| Вызов клиента | Ответ и гарантия |
|---|---|
| `status`, `doctor`, `get-metrics` | Снимок наблюдений, источник, время и `lastSuccessUtc`. Неизвестные поля `null`; отсутствие шины не доказывает, что ПК offline |
| `create-plan(type, params)` | Агент сопоставляет тег с закрытым типом параметров. Возвращает `PlanId`, шаги, источники, target, ревизии и срок годности, права, риски, покрытие отката. Не запускает установку |
| `approve-plan(planId, expectedRevision)` | Согласие только на показанный набор, UID и условия. Не заменяет Polkit и не переживает изменение плана |
| `run-job(type, params: {planId})` | Сервер выдаёт `{jobId, planId, phase}`. При повторе — **существующее** задание, включая законченный результат. Тип обязан совпадать с планом; клиент не назначает чужой `jobId` |
| `get-job(jobId)`, `jobs`, `logs(jobId, cursor, limit)` | Снимок, фазы, результаты по менеджерам, безопасные действия и курсор. Только задания этого владельца; ограниченная выдача |
| `watch(epoch, afterSeq)` | Дельты после курсора либо `CursorExpired` со ссылкой на новый снимок. Разрыв связи не отменяет задание |
| `cancel-job(jobId)` | Запрос намерения; до границы — ожидать безопасного места и очистить временные данные. После входа в критическую фазу — `UnsafeToCancel`, нет кнопки отмены |

Например, `{"v":1,"type":"TrialDns","params":{"planId":"17"}}` с уже согласованным планом → `{"jobId":"41","planId":"17","phase":"Ready"}`. Это **пример данных**, не доступная сейчас команда. Для долгих проверок без эффектов агент создаёт план чтения и `JobId`, даже если предварительный диалог не требуется. Фиксация пары `(владелец, PlanId) → JobId` и очереди — одна транзакция; отдельная блокировка ресурса исключает две активные установки даже по разным планам. Не принимать произвольный JSON `params`: закрытое объединение, предел 64 КиБ, не более 128 шагов, лимиты строк, проверка ID и контекста на обеих границах.

### События agent → адаптер Tauri → окно

Общие поля: `v`, `epoch`, `seq`, `observedAtUtc`; для заданий также `jobId`, `planId`. Объявленный интервал — не доказательство свежести. Данные идут **из** проверившего компонента, а не генерируются таймером GUI.

| Имя Tauri | Полезная нагрузка v1 | Обработка |
|---|---|---|
| `metrics-tick` | `cpu` и `cpuCores` в %, `ram`, `ramTotal`, `diskUsed`, `diskTotal` в байтах, `netRx`, `netTx` в B/s, `temp` в °C; `null` для недоступного | Шаг 1000 мс, окно 60 точек. Пропуск оставляет разрыв, не дорисовывает нули. `get-metrics` также даёт uptime, hostname, kernel и обнаруженный snapshot backend |
| `updates-available` | `count` программ, `critical` подтверждённых применимых исправлений, `message`, `sources`, `lastSuccessUtc`; счётчики могут быть `null` | Дедупликация приложений, отдельный счётчик пакетов и недоступных источников, ссылка на план |
| `net-status` | `dns`, `dnsLatency`, `mirrors`, `online`, `relay`, `relayLatency`, `profileId`, `reason`; неизвестное `null`, задержки в мс | Не объявлять отключение по одному CDN, не считать локальный stub внешним DNS |
| `job-progress` | `phase`, `stepId`, `percent` (0–100 или `null`), `message`, `canCancel` | Отрисовать подтверждённую фазу; критический шаг неотменяем |
| `job-complete` | `outcome`, `success`, `steps`, `message`, `recovery` | `success=true` только при полном успехе; `Partial`, `Failed`, `Cancelled` не превращаются в успех |

При переподключении открыть подписку, получить снимок с курсором, применить только события **строго после** него, отбросить дубли; при дыре/смене `epoch`/усечении истории запросить новый снимок. Журнал задания переживает закрытие окна. Для телеметрии после разрыва новый замер, а не повтор старых точек как живых. Неизвестный результат никогда не преобразуется в успех по таймауту.

Ошибка: `{code, message, retryable, jobId?, planId?, stepId?, recovery?}`. `UnsupportedBackend`, `AccessDenied`, `NoPolkitAgent`, `PlanChanged`, `SignatureInvalid`, `PolicyBlocked`, `UnsafeToCancel`, `RecoveryRequired` требуют решения или исправления условий. `SourceUnavailable`, `Busy`, `Timeout` допускают только ограниченный повтор безопасной пробы. `CursorExpired` требует перечитать снимок. Полный stderr, конфигурации и токены в сообщение не попадают.

### Планируемый allowlist System D-Bus / Polkit

Префикс каждого действия **`io.github.Knox1986X.MeshPilot.`**. В этапе 1 нет ни политики, ни установленных systemd units, ни зарегистрированного имени на шине.

| Метод помощника | Суффикс Polkit | Допустимые данные и ограничения |
|---|---|---|
| `PrepareDnsTrial` | `trial-dns` | Идентичность профиля, кандидат, ревизия; helper сам обнаруживает владельца, проверяет split DNS, готовит таймер |
| `ConfirmDnsTrial` | `confirm-dns` | Только токен пробы этого UID, непросроченная ревизия и независимые успешные проверки |
| `RestoreNetwork` | `restore-network` | Только идентификатор записи MeshPilot; сравнение текущих и записанных значений перед возвратом. Аварийный таймер работает без интерактивного запроса |
| `ApplyMirrors` | `apply-mirrors` | ID проверенных совместимых источников, без переданных путей или готового текста mirrorlist |
| `CreateSnapshot` | `create-snapshot` | Только обнаруженная системная конфигурация и ссылка на план; результат содержит покрытие |
| `UpgradeOfficial` | `upgrade-official` | Полностью повторно проверенный системный план, версии, подписи, блокировка менеджера, место, питание. Без AUR и произвольных опций |

Helper берёт уникальное имя отправителя из сообщения системной шины и проверяет Polkit для этого субъекта и **конкретного действия**; не верит UID/PID из тела запроса. После интерактивного ожидания повторно сверяет план и состояние. Отказ / отсутствие агента → только чтение с причиной. Никакого ввода пароля MeshPilot, беспарольного sudo и общего метода выполнения команд.
