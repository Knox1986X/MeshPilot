# MeshPilot · архитектура и IPC

**Что действительно есть:** [дерево со статусами](../README.md#дерево-и-границы-этапа), CLI, пассивный Linux-адаптер, чистая модель задания, общие для CLI и Dashboard измерения CPU, RAM, корневой ФС и трафика по интерфейсам. Доступность интернета и DNS пока не проверяется. Session D-Bus, helper и поток событий ниже — **предложенный контракт**, не API работающего сервиса. [Переходы и восстановление](STATE-MACHINES.md) · [бэкап v1](BACKUP.md) · [проверки](STATE.md).

## Процессы и границы доверия

```text
Сейчас, пользователь Linux
  CLI meshpilot → meshpilot-linux → чтение os-release/маркера CachyOS и метаданных утилит/библиотек окна
  Svelte → WebView Tauri → управление своим окном (drag/minimize/maximize/close)
  CLI и локальная команда Tauri read_ram() → meshpilot-linux::ram_snapshot → /proc/meminfo
  CLI и локальная команда Tauri read_cpu() → meshpilot-linux::cpu_snapshot → /proc/stat
  CLI и локальная команда Tauri read_root_fs() → meshpilot-linux::root_fs_snapshot → statvfs("/")
  CLI и локальная команда Tauri read_network_io() → meshpilot-linux → /proc/net/dev
  meshpilot-core: модели и правила, не делает I/O

Предложено, этапы 2–6
  CLI ──────────┐
  Desktop/Tauri ├─ Session D-Bus ─ meshpilot-agent.service (UID пользователя, Tokio)
  Tray ─────────┘                    ├─ meshpilot-core: правила, план, отчёт
                                    ├─ meshpilot-net/linux: проверки без root
      недоверенные новости/профили → ├─ ограниченный импорт как данных
      облако, только App Folder  ↔   ├─ meshpilot-sync: AEAD, ревизии, локальная очередь
                                    │
                    граница прав    └─ System D-Bus: тип действия + ссылка на план
                                          ↓ UID отправителя, Polkit, повторная валидация
                                     meshpilot-helper.service (root, allowlist)
                                       ├─ управляющий соединением / менеджер пакетов
                                       └─ защищённый журнал + независимый таймер отката

Позже, Android: Kotlin UI и системные согласия → общие модели Rust и sync
                 VpnService / Keystore / установщик остаются на стороне Android
```

Окно не запускает shell. Нет HTTP API для управления системой. Полученный по IPC `JobId` — ссылка, не полномочие. Agent и процессы одного UID не являются границей безопасности друг для друга. Helper не читает пользовательский журнал как доказательство согласия: восстанавливает **свой** канонический план по доверенным системным данным, проверяет субъект вызова и авторизацию. Конфигурации VPN, тексты новостей, сеть, облако и весь WebView недоверенны. Не передавать helper шаблоны команд, пути для перезаписи, окружение, аргументы менеджера пакетов или имена произвольных служб. Сборка AUR, подписки, уведомления, GUI и Dropbox не работают от root.

### Реализовано: один снимок RAM

`meshpilot_core::RamObservation` — данные без I/O. `StatusReport.ram: Option<RamObservation>` добавлено в JSON v1 без изменения старых полей и кодов выхода. Команда `read_ram()` возвращает тот же объект или `null`. Разрешение `allow-read-ram` доступно только локальному окну `main`. IPC не принимает имя файла, PID, команду, интервал или аргументы чтения.

| Поле результата | Смысл |
|---|---|
| `used_bytes` | `(MemTotal − MemAvailable) × 1024` байт, без подстановки `MemFree` |
| `total_bytes` | `MemTotal × 1024` байт. Виден объём памяти ядра, не бюджет cgroup |
| `source` | Только `/proc/meminfo`, одно чтение объёмом до 64 КиБ |
| `observed_at_utc` | Время системных часов после чтения, RFC 3339 UTC с миллисекундами. Не подтверждение синхронизации часов и не `last_success_utc` проверки обновлений |

Неполные или повторные целевые поля, неверная единица, ошибка чтения/часов, переполнение, нулевой общий объём, `MemAvailable > MemTotal` либо число вне точного целого JSON для JavaScript → весь снимок `null`. Настоящее `used_bytes: 0` допустимо. Окно проверяет ответ IPC, показывает источник и время, не хранит в файле и не рисует график по одиночной точке. При ошибке ручного обновления старый замер не выдаётся за новый. Независимые CLI и GUI получают отдельные снимки одного адаптера, не обещают совпадения байтов в разные моменты.

### Реализовано: загрузка CPU за интервал

`StatusReport.cpu: Option<CpuObservation>` и `read_cpu()` используют одну функцию Linux. Окну `main` добавлена только `allow-read-cpu`, без параметров или произвольного доступа к файлам. `spawn_blocking` выносит чтение и паузу с потока UI и async executor; неблокирующий захват допускает один активный замер CPU на процесс окна. Новые вызовы во время него не ставятся в очередь. `doctor` эту пробу не запускает.

- Два открытия фиксированного `/proc/stat`. Нужна первая целая строка `cpu` до 512 байт, с восемью обязательными беззнаковыми счётчиками и не более двух гостевых. Строки `cpu0`, `intr` и остальной файл не разбираются. В двух строках должна быть одна раскладка, ни один счётчик не убывает. Это консервативно, в частности Linux допускает уменьшение `iowait`.
- `total_ticks` — сумма **разностей** `user`, `nice`, `system`, `idle`, `iowait`, `irq`, `softirq`, `steal`. `busy_ticks` — та же сумма без `idle` и `iowait`; включает `steal`, поэтому это доля не-простоя, а не гарантия полезной работы гостя. `guest`/`guest_nice` уже учтены. `usage_percent = 100 × busy_ticks / total_ticks`; CLI/карточка округляют для показа, JSON хранит отношение без такого округления.
- `interval_ms` — фактическая разность монотонных отметок после чтений в целых миллисекундах, а не константа сна. Пауза запрошена на 500 мс; интервалы короче 500 мс или длиннее 5 с отбрасываются. `observed_at_utc` — системное время **второго** чтения, `source = /proc/stat`. Это не время отрисовки, не ряд измерений и не статистика по отдельному CPU или cgroup.
- Ошибки чтения/формата/часов, изменившийся набор полей, регрессия, переполнение, неточный для WebView счётчик или отсутствие тиков → `null`. Отказ CPU не влияет на RAM. При `busy_ticks = 0` и положительном знаменателе результат 0 % действителен. Эти краткие пробы не создают фоновых заданий, не пишут в журнал и не требуют Polkit.

### Реализовано: место на корневой ФС

`StatusReport.root_fs: Option<RootFsObservation>` и `read_root_fs()` используют [один адаптер](../crates/meshpilot-linux/src/root_fs.rs). Путь `/` фиксирован; `rustix::fs::statvfs` — безопасный API в зависимости только для Linux. Нет обхода каталогов, разбора вывода `df`, перечисления устройств или доступа к другим mountpoints. `allow-read-root-fs` доступно только локальному окну `main`. Даже медленное чтение идёт на рабочем потоке, с одним активным вызовом на источник, отдельно от CPU. `doctor` не запускает измерение.

| Поле `root_fs` | Как получено |
|---|---|
| `total_bytes` | `f_blocks × f_frsize` |
| `used_bytes` | `(f_blocks − f_bfree) × f_frsize` |
| `available_bytes` | `f_bavail × f_frsize`: место, сообщённое ФС для непривилегированного пользователя |
| `source`, `observed_at_utc` | `statvfs(/)` и UTC после чтения (RFC 3339 с миллисекундами) |

Требуются `f_bavail ≤ f_bfree ≤ f_blocks`, положительные размер фрагмента и ёмкость, байты в диапазоне точных целых WebView. Ошибка вызова, переполнение, невозможные счётчики или время → весь объект `null`. `total_bytes − used_bytes − available_bytes` — свободное, но недоступное место; не прибавлять его к занятому. Нулевые занятое или доступное место допустимы. Карточка, кольцо и легенда делят один проверенный ответ; нет второго чтения для диаграммы и нет выдачи прошлых чисел при отказе. Снимок не учитывает стоимость обновления, inode, квоты конкретного файла или место на отдельном `/boot`.

### Реализовано: трафик по интерфейсам

`StatusReport.network_io: Option<NetworkIoObservation>` и локальная команда `read_network_io()` используют [один адаптер](../crates/meshpilot-linux/src/network_io.rs). Разрешение только окну `main`, без аргументов: WebView не передаёт путь, имя интерфейса или время ожидания. Не открываем сокеты, не опрашиваем внешние узлы, не запускаем `ip`. `doctor` эту пробу не делает.

- Два чтения фиксированного `/proc/net/dev` в сетевом пространстве процесса. Лимиты на каждое: 64 КиБ, 256 интерфейсов, целая таблица с заголовком RX/TX и 16 беззнаковыми полями в строке. Сохраняются только имя и два счётчика байтов (позиции 0 и 8). Поддерживаются однозначные печатные ASCII-имена Linux до 15 байт без пробелов, `/` и `:`. Дубликат, неподдерживаемый формат или превышение лимита → `network_io: null`, не частичный отчёт.
- `source = /proc/net/dev`, `observed_at_utc` — время второго чтения в UTC. `interval_ms` — фактически прошедший монотонный интервал в целых мс (до усечения должен быть в пределах 500 мс – 5 с). Для двух источников в `status` одна пауза, но **свои** отметки после своих чтений. Отказ одного источника не скрывает результат другого; не создаётся дополнительный поток CLI. В окне интервал измеряется на рабочем потоке; отдельный `try_lock` не накапливает очередь повторов.
- `interfaces` — имена во втором чтении, в лексикографическом порядке. Для каждого `rates` содержит `rx_delta_bytes`, `tx_delta_bytes` и `rx_bytes_per_sec`, `tx_bytes_per_sec` = соответствующая дельта × `1000 / interval_ms`. Два накопленных `u64` вычитаются **до** преобразования в число WebView. При появлении имени, регрессии RX/TX или неточной для JSON дельте только эта пара `rates: null`. Удалённое имя не остаётся в списке. Если имя было переиспользовано между чтениями без убывания счётчиков, один procfs этого различить не позволяет.
- Пустой список ≠ отсутствие источника ≠ измеренные 0 Б/с. `lo` учитывается отдельно и подписан, не заменяет внешний интерфейс. Не определяем маршрут по умолчанию и не складываем VPN и нижележащий интерфейс. Выбор в UI локальный (по умолчанию первый не-`lo`, иначе `lo`); карточка и footer меняются без повторного IPC. Нет данных о пакетах, адресах, доменах или содержимом трафика в отчёте.

### Реализовано: время работы системы

`StatusReport.uptime: Option<UptimeObservation>` и локальная команда `read_uptime()` используют [один адаптер](../crates/meshpilot-linux/src/uptime.rs). Разрешение только окну `main`, без аргументов. Не открываем сокеты и не запускаем сторонние утилиты. `doctor` эту пробу не делает.

| Поле `uptime` | Как получено |
|---|---|
| `uptime_seconds` | Целая часть первого поля `/proc/uptime` — секунды с момента загрузки ядра (не время до перезагрузки, не время сессии пользователя) |
| `source`, `observed_at_utc` | `/proc/uptime` и UTC после чтения (RFC 3339 с миллисекундами) |

Одно чтение файла объёмом до 64 КиБ. Файл Linux — ровно два поля `seconds.centiseconds`, разделённые одним пробелом и завершённые переводом строки. Дробная часть — тот же счётчик с точностью до сотых, поэтому показываем целую часть, а не округление. Изменённая разметка, лишние поля, знак, экспонента, переполнение или отсутствующие часы → `uptime: null`, не 0 с. Измеренные 0 с (свежая загрузка) допустимы.

В CLI uptime — быстрая проба, как RAM: не входит в общую с CPU паузу 500 мс и не добавляет задержки в `status`. В окне снимок запрашивается при открытии и по кнопке «Обновить время работы»; секундного таймера и фонового опроса нет, поэтому подпись панели «Среда» не перерисовывается каждую секунду. CLI и GUI получают отдельные чтения одного адаптера и не обещают совпадения секунд в разные моменты.

### Реализовано: версия ядра

`StatusReport.kernel: Option<KernelObservation>` и локальная команда `read_kernel()` используют [один адаптер](../crates/meshpilot-linux/src/kernel.rs). Разрешение только окну `main`, без аргументов. Не запускаем `uname` или другие внешние программы — только чтение `/proc/version`. `doctor` эту пробу не делает.

| Поле `kernel` | Как получено |
|---|---|
| `version` | Второе слово единственной строки `/proc/version` (`Linux version <версия> (кто собирал) ...`) — версия работающего ядра, дословно, включая `+`, `-`, `.` |
| `source`, `observed_at_utc` | `/proc/version` и UTC после чтения (RFC 3339 с миллисекундами) |

Одно чтение файла объёмом до 64 КиБ. Требуется ровно одна строка, начальные слова `Linux` `version` и версия — 1–64 печатных ASCII-символа без пробелов. Изменённая разметка, вторая строка, неверный заголовок или недопустимые символы → `kernel: null`, не пустая строка. Это версия ядра, а не пакет kernel в pacman и не `VERSION_ID` os-release.

В CLI — быстрая проба, как RAM/аптайм: не входит в общую с CPU паузу 500 мс и не добавляет задержки в `status`. В окне снимок запрашивается при открытии и по кнопке «Обновить версию ядра»; та же версия показана в метке «Kernel» списка статусов. Секундного таймера и фонового опроса нет. Версия ядра постоянна за загрузку, поэтому приёмка в VM сверяет её по точному равенству с независимым чтением гостя, а не по дельтам.

### Размещение и владение (пока ничего не создаётся)

| Данные | Владелец и путь | Правило |
|---|---|---|
| Конфигурация | пользователь, `~/.config/meshpilot/` | Версия, схема, атомарная замена, последняя рабочая версия; при повреждении только диагностика |
| Задания, события, обезличенные логи | пользователь, `~/.local/state/meshpilot/` | Режимы 0700/0600; изменения фазы и курсор событий в одной транзакции |
| Данные, зашифрованные бэкапы | пользователь, `~/.local/share/meshpilot/` | Секреты отдельно, не экспортировать ключи туннелей и OAuth |
| Доказательство плана и изменений | root, `/var/lib/meshpilot/` | Каталог root-only, доверенные дескрипторы, не следовать пользовательским ссылкам |
| Планирование | `meshpilot-agent.service`, `meshpilot-helper.service`, `meshpilot-*.timer` | Пользовательская служба не получает системные права. Таймер отката — системный, вне agent |

Первые три пути — значения по умолчанию XDG. Для root не использовать переменные окружения вызывающего клиента. В журнале: причина, стадия, код результата, длительность; по умолчанию без DNS-истории, профилей с секретами и полного stdout сторонних программ.

## Модель этапа 1

[Исходный Rust](../crates/meshpilot-core/src/jobs.rs) — источник истины. Сокращённая сигнатура типов (без атрибутов сериализации):

```rust
pub struct JobId(pub u64);
pub struct PlanId(pub u64);
pub struct Plan { pub id: PlanId, pub steps: Vec<PlanStep> }
pub struct PlanStep {
    pub operation: Operation,
    pub reason: String,
    pub authority: Authority,
    pub reversible: bool,
    pub on_failure: OnFailure,
}
pub enum Operation { Diagnose, TrialDns, UpgradeOfficial, UpgradeUserFlatpak }
pub enum Outcome { Succeeded, Partial, Failed }
pub enum JobPhase { AwaitingConsent, Ready, Running, Critical, Finished(Outcome), Cancelled }
```

`JobBook::register` не выполняет план. Одинаковый `PlanId` и то же содержание → прежний `JobId`; другое содержание → `PlanChanged`, пустой план → `EmptyPlan`. `JobPhase::transition` нельзя заставить начать работу до `Approve` или отмениться в `Critical`. Это проверено в памяти, не тест долговечности будущего журнала. ID на JSON-границе — десятичные строки (без потери точности JavaScript), в D-Bus допустим `uint64`. При реальном IPC UID, установка и ревизия плана привязываются сервером; счётчики должны сохраняться и не переиспользоваться после падения.

## IPC v1 — предложено

Имя на соответствующей шине **`io.github.Knox1986X.MeshPilot`**, объект `/io/github/Knox1986X/MeshPilot`, версионированный интерфейс `io.github.Knox1986X.MeshPilot.V1`. Одинаковое имя на двух разных шинах не означает одинаковые полномочия. Клиент проверяет `protocolVersion`, `capabilities` и `epoch` через `Hello`. Неизвестный major, действие или поле входного плана — отказ **до** любого эффекта.

| Вызов клиента | Ответ и гарантия |
|---|---|
| `status`, `doctor`, `get-metrics` | Снимок наблюдений, источник, время и `lastSuccessUtc`. Неизвестные поля `null`; отсутствие шины не доказывает, что ПК offline |
| `create-plan(type, params)` | Агент сопоставляет тег с закрытым типом параметров. Возвращает `PlanId`, шаги, источники, target, ревизии и срок годности, права, риски, покрытие отката. Не запускает установку |
| `approve-plan(planId, expectedRevision)` | Согласие только на показанный набор, UID и условия. Не заменяет Polkit и не переживает изменение плана |
| `run-job(type, params: {planId})` | Сервер выдаёт `{jobId, planId, phase}`. При повторе — **существующее** задание, включая законченный результат. Тип обязан совпадать с планом; клиент не назначает чужой `jobId` |
| `get-job(jobId)`, `jobs`, `logs(jobId, cursor, limit)` | Снимок, фазы, результаты по менеджерам, безопасные действия и курсор. Только задания этого владельца; ограниченная выдача |
| `watch(epoch, afterSeq)` | Дельты после курсора либо `CursorExpired` со ссылкой на новый снимок. Разрыв связи не отменяет задание |
| `cancel-job(jobId)` | Запрос намерения; до границы — ожидать безопасного места и очистить временные данные. После входа в критическую фазу — `UnsafeToCancel`, нет кнопки отмены |

Например, `{"v":1,"type":"TrialDns","params":{"planId":"17"}}` с уже согласованным планом → `{"jobId":"41","planId":"17","phase":"Ready"}`. Это **пример данных**, не доступная сейчас команда. Для долгих проверок без эффектов агент создаёт план чтения и `JobId`, даже если предварительный диалог не требуется. Фиксация пары `(владелец, PlanId) → JobId` и очереди — одна транзакция; отдельная блокировка ресурса исключает две активные установки даже по разным планам. Не принимать произвольный JSON `params`: закрытое объединение, предел 64 КиБ, не более 128 шагов, лимиты строк, проверка ID и контекста на обеих границах.

### События agent → адаптер Tauri → окно

Общие поля: `v`, `epoch`, `seq`, `observedAtUtc`; для заданий также `jobId`, `planId`. Объявленный интервал — не доказательство свежести. Данные идут **из** проверившего компонента, а не генерируются таймером GUI.

| Имя Tauri | Полезная нагрузка v1 | Обработка |
|---|---|---|
| `metrics-tick` | `cpu` и `cpuCores` в %, `ram`, `ramTotal`, `diskUsed`, `diskTotal` в байтах, `netRx`, `netTx` в B/s, `temp` в °C; `null` для недоступного | Шаг 1000 мс, окно 60 точек. Пропуск оставляет разрыв, не дорисовывает нули. `get-metrics` также даёт uptime, hostname, kernel и обнаруженный snapshot backend |
| `updates-available` | `count` программ, `critical` подтверждённых применимых исправлений, `message`, `sources`, `lastSuccessUtc`; счётчики могут быть `null` | Дедупликация приложений, отдельный счётчик пакетов и недоступных источников, ссылка на план |
| `net-status` | `dns`, `dnsLatency`, `mirrors`, `online`, `relay`, `relayLatency`, `profileId`, `reason`; неизвестное `null`, задержки в мс | Не объявлять отключение по одному CDN, не считать локальный stub внешним DNS |
| `job-progress` | `phase`, `stepId`, `percent` (0–100 или `null`), `message`, `canCancel` | Отрисовать подтверждённую фазу; критический шаг неотменяем |
| `job-complete` | `outcome`, `success`, `steps`, `message`, `recovery` | `success=true` только при полном успехе; `Partial`, `Failed`, `Cancelled` не превращаются в успех |

При переподключении открыть подписку, получить снимок с курсором, применить только события **строго после** него, отбросить дубли; при дыре/смене `epoch`/усечении истории запросить новый снимок. Журнал задания переживает закрытие окна. Для телеметрии после разрыва новый замер, а не повтор старых точек как живых. Неизвестный результат никогда не преобразуется в успех по таймауту.

Ошибка: `{code, message, retryable, jobId?, planId?, stepId?, recovery?}`. `UnsupportedBackend`, `AccessDenied`, `NoPolkitAgent`, `PlanChanged`, `SignatureInvalid`, `PolicyBlocked`, `UnsafeToCancel`, `RecoveryRequired` требуют решения или исправления условий. `SourceUnavailable`, `Busy`, `Timeout` допускают только ограниченный повтор безопасной пробы. `CursorExpired` требует перечитать снимок. Полный stderr, конфигурации и токены в сообщение не попадают.

### Планируемый allowlist System D-Bus / Polkit

Префикс каждого действия **`io.github.Knox1986X.MeshPilot.`**. В этапе 1 нет ни политики, ни установленных systemd units, ни зарегистрированного имени на шине.

| Метод помощника | Суффикс Polkit | Допустимые данные и ограничения |
|---|---|---|
| `PrepareDnsTrial` | `trial-dns` | Идентичность профиля, кандидат, ревизия; helper сам обнаруживает владельца, проверяет split DNS, готовит таймер |
| `ConfirmDnsTrial` | `confirm-dns` | Только токен пробы этого UID, непросроченная ревизия и независимые успешные проверки |
| `RestoreNetwork` | `restore-network` | Только идентификатор записи MeshPilot; сравнение текущих и записанных значений перед возвратом. Аварийный таймер работает без интерактивного запроса |
| `ApplyMirrors` | `apply-mirrors` | ID проверенных совместимых источников, без переданных путей или готового текста mirrorlist |
| `CreateSnapshot` | `create-snapshot` | Только обнаруженная системная конфигурация и ссылка на план; результат содержит покрытие |
| `UpgradeOfficial` | `upgrade-official` | Полностью повторно проверенный системный план, версии, подписи, блокировка менеджера, место, питание. Без AUR и произвольных опций |

Helper берёт уникальное имя отправителя из сообщения системной шины и проверяет Polkit для этого субъекта и **конкретного действия**; не верит UID/PID из тела запроса. После интерактивного ожидания повторно сверяет план и состояние. Отказ / отсутствие агента → только чтение с причиной. Никакого ввода пароля MeshPilot, беспарольного sudo и общего метода выполнения команд.
