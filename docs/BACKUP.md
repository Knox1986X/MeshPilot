# MeshPilot · предложенный формат бэкапа v1

**Этап 1:** созданы две JSON Schema, не криптомодуль. Бэкап не создавался, OAuth, AEAD и восстановление не реализованы. Незашифрованный `STATE.md` содержит только статус разработки; это не пользовательский бэкап.

**Два разных доступа.** Arena пишет контрольную точку и проектные документы только в `/MeshPilot/`. Будущее приложение при явном подключении использует OAuth Authorization Code с PKCE, **только Dropbox App Folder**, а не Full Dropbox. Пути API приложения относительны корню App Folder. Отсутствие облака не отключает локальную диагностику или пакетную транзакцию. Никаких секретов Dropbox в GUI-бандле, репозитории, CI и журналах.

## Конверт и полезная нагрузка

[Конверт v1](schemas/backup-v1.schema.json) содержит только публичный заголовок и шифротекст. [Схема открытого текста](schemas/profile-payload-v1.schema.json) — белый список полей **внутри** AEAD. Иллюстрация содержимого после расшифровки, без ключей и сведений реального устройства:

```json
{
  "schemaVersion": 1,
  "preferences": { "language": "ru", "theme": "dark" },
  "profiles": []
}
```

| Поле конверта | Смысл |
|---|---|
| `format`, `version`, `algorithm` | Ровно `MeshPilot`, `1`, `XChaCha20-Poly1305-IETF`; неизвестная версия/алгоритм не понижает защиту, импорт прекращается |
| `streamId`, `revisionId` | Случайные независимые публичные идентификаторы 128 бит в hex, не hostname, не время и не JobId |
| `parents` | 0 родителей у начала, 1 у изменения, 2 у явного объединения. Не подменять родителя временем изменения файла |
| `keyId` | Непрозрачная ссылка на версию ключа, не ключ и не его пароль |
| `nonce` | Свежие 24 случайных байта из системного CSPRNG, канонический Base64. Новый открытый текст — новый nonce под тем же ключом |
| `ciphertext` | Канонический Base64 от шифротекста вместе с 16-байтной меткой AEAD |

AEAD — из поддерживаемой криптобиблиотеки (например, libsodium); не писать шифр или проверку тега самостоятельно. Ключ данных — 32 случайных байта. AAD — UTF-8 от RFC 8785 JCS для всех полей конверта **кроме `ciphertext`**, включая версию, тип, nonce, stream, keyId, родителей и ревизию. Не принимать повторяющиеся ключи JSON. Конверт ограничить 2 МиБ до парсинга, распакованный открытый текст — 1 МиБ, глубину — 8, число профилей — 64. Нет сжатия и вложенных архивов. Проверять длину декодированных значений, каноничность Base64, уникальность profileId и ревизий, принадлежность stream. Одна JSON Schema не проверяет криптографию, владение профилем или свежесть.

Ключ данных и OAuth-токены — в системном хранилище секретов пользователя; на Android ключ данных может быть обёрнут неэкспортируемым ключом Keystore. Не класть ключ в App Folder или рядом с копией. Новый ПК получает ключ только через отдельно согласованный защищённый перенос/сопряжение. Нет ключа — нет расшифровки, не создавать новый ключ поверх старого бэкапа. Ротация ключа создаёт новую ревизию, прежнюю не перезаписывает. Утрата всех копий ключа означает невозможность восстановления.

v1 экспортирует только выбранные настройки интерфейса и абстрактные правила профиля. Нет VPN/Wi-Fi-секретов, refresh-токенов, Telegram/SMTP, содержимого keyring, журналов доменов, команд, абсолютных путей, SSID, адресов узлов или привилегированных планов. Неизвестные поля отклоняются, а не переносятся как расширения.

## Ревизии и восстановление

1. Без сети сохранить зашифрованную локальную очередь в `~/.local/share/meshpilot/` через временный файл 0600, fsync, rename и fsync каталога. Повтор загрузки отправляет уже запечатанные байты, а не переиспользует nonce для нового сообщения.
2. Файл ревизии внутри App Folder: `/backups/v1/{streamId}/{revisionId}.json`, режим создания без перезаписи. Указатель на вершину обновлять только с ожидаемым **Dropbox `rev`**. Это не `revisionId` из зашифрованного формата.
3. При конфликте прочитать обе вершины, проверить AEAD и общих родителей. Не выбирать по времени. Для расходящихся изменений сохранить обе ревизии; после просмотра создать merge с двумя родителями и условно обновить вершину. Старой копией новую не затереть. Сбой облака — локальная очередь, не успех синхронизации.
4. При восстановлении считать указатель подсказкой, сверить header/path/stream, аутентифицировать весь конверт **до** использования открытого текста. Отвергнуть replay относительно локально известной вершины. На новом устройстве без доверенного якоря один только AEAD доказывает подлинность, но не то, что копия последняя; показать это ограничение.
5. Разобрать строго по версии, сопоставить профили с локальными соединениями только вручную, показать diff: что переносится, пропускается и почему. Предпросмотр ничего не применяет. Отдельное согласие — на локальные пользовательские настройки; любые системные изменения требуют нового локального плана и обычной авторизации. Бэкап приложения — не снапшот системы.

**Критерии этапа 6:** изменённый бит, перестановка заголовка, неверный ключ, повтор nonce в генераторе теста, сломанный JSON, неизвестная версия, лишнее поле, чужая вершина, два офлайн-клиента, отзыв OAuth, отсутствие keyring. Во всех отказах исходное состояние остаётся доступным, а причина видна без вывода секрета.

Структурные проверки схем (Python с `jsonschema==4.25.1`): `python3 tests/backup_schema.py`. Они проверяют версии, длины, запрет лишних полей и родителей-дубликатов. Положительный синтаксический пример **не** является аутентифицированным бэкапом.
