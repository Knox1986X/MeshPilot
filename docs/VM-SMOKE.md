## Как устроен тест

1. `media.sh` принимает только закреплённый профиль. Передача ограничена HTTPS, временем и размером. Явный HTML вместо файла — ошибка доставки, даже при HTTP 200. Источники — зеркала и архив издателя, не произвольный пользовательский URL. Для Handheld дополнительно требуем совпадения пина с файлом `.iso.sha256` дистрибутива. [Отдельная запись контрольной суммы](https://github.com/neramc/linuxhub/blob/0a9ef22ab26dad420939f6c4c2a7d18bc5e6aa17/src/data/releases/cachyos.json) не заменяет эту проверку.
2. `verify.sh` офлайн сверяет SHA-256 байтов и отделённую OpenPGP-подпись ожидаемого ключа `882DCFE48E2051D48E2562ABF3B607488DB35A47`. [Открытый ключ](https://github.com/CachyOS/CachyOS-PKGBUILDS/blob/0669f94df9b4970886b3c3bbee13711aab7db5a8/cachyos-keyring/cachyos.gpg) закреплён также по хешу. Keyring временный. Ошибка хеша, подписи или отпечатка — стоп, без подбора другого хеша. `run.sh` повторяет проверку перед извлечением ядра; это относится и к локально предоставленному носителю.
3. QEMU/KVM работает как обычный пользователь одноразового Ubuntu runner. Ядро и initramfs — из выбранного ISO, испытуемые бинарники — из текущего checkout по lockfiles. У гостя только два read-only CD и рабочий слой в RAM. Нет NIC, пишущего диска, SSH, QGA, общих каталогов и передачи ключей хоста. Зависимости сборки устанавливаются только на runner.
4. Разовая гостевая служба проверяет DMI стенда, виртуализацию, ядро, read-only mountpoints и наличие только loopback. CLI, окно и наблюдатель запускаются как `liveuser` с `no_new_privs` и временным HOME/XDG. Используется **дисплей гостевой Plasma**, X11/XWayland. `LD_LIBRARY_PATH` только у вспомогательного `xdotool`, не у MeshPilot. Sandbox WebKit не отключаем.

**Условие успеха текущего стенда:** по отдельному UART получена ровно последовательность `GUEST → CLI → SESSION → WINDOW → RAM_CARD → CPU_CARD → ROOT_FS_CARD → NET_IO_CARD → UPTIME_CARD → KERNEL_CARD → OS_VERSION_CARD → HOSTNAME_CARD → UNCHANGED → PASS` с идентификатором текущего запуска **и** код QEMU равен 0. По отдельности метки означают:

- `GUEST`: прошли проверки среды и носителей.
- `CLI`: `meshpilot status --json` и `meshpilot doctor --json --dry-run` вернули 0. Проверены исходный `os_id`, обнаружение CachyOS и pacman, поля `null`, байты, источник и время RAM относительно вызова CLI, диагностика файлов GUI и пустой HOME после CLI. Для CPU проверяются UTC, фактический интервал в пределах длительности вызова и процент из дельт. Внешняя пара чтений `/proc/stat` до/после процесса независимо ограничивает обе дельты — занятую и простоя. Для `root_fs` проверяем источник и UTC, ёмкость, занятые и доступные пользователю байты, кратность `f_frsize` и остаток свободных недоступных блоков. `fs_witness.py` от того же `liveuser` независимо читает `os.statvfs("/")` до, во время и после работы испытуемого процесса. Сравниваем с наблюдавшимися границами, при стабильных счётчиках — точное совпадение. Для `network_io` внешние чтения `/proc/net/dev` ограничивают дельты каждого направления; скорости пересчитываются за фактический интервал. Временные окна CPU и сети в CLI должны перекрываться хотя бы на 450 мс — проверка против двух последовательных пауз, без лимита на всю загрузку процесса. Для `uptime` проверяем источник `/proc/uptime`, UTC и целые секунды в границах независимых чтений `fs_witness.py` до/после процесса (аптайм монотонно растёт, поэтому верхняя граница может опережать на 1 с). Для `kernel` проверяем источник `/proc/version`, UTC и версию в границах независимых чтений — версия ядра постоянна за загрузку, поэтому границы совпадают и сверка по точному равенству. Для `os_version` проверяем источник `/etc/os-release`, UTC и поле `VERSION` в границах независимых чтений — значение за загрузку не меняется, поэтому граница — точное. Если поле `VERSION` в образе отсутствует (как в Arch-совместном CachyOS Live), `fs_witness.py` фиксирует отсутствие и CLI обязан вернуть честный `os_version: null`, а не выдуманную версию. Для `hostname` проверяем источник `/proc/sys/kernel/hostname`, UTC и имя в границах независимых чтений `fs_witness.py` — имя узла могут сменить в работе, поэтому допустимо любое из наблюдавшихся значений.
- `SESSION`: от дисплея получены ненулевые размеры. Наличие `DISPLAY` само по себе не доказательство.
- `WINDOW`: наблюдатель нашёл **видимое** окно с заголовком MeshPilot и PID именно запущенного живого процесса. Сеанс, чужое окно или успешный `ldd` не проходят этот критерий.
- `RAM_CARD` (этап 2): независимый наблюдатель AT-SPI в дереве того же PID прочитал имя карточки из **видимых** подписей. Проверены источник, единицы, использованный и общий объём, UTC-время в пределах запуска окна. Общий объём сверяется с `/proc/meminfo` гостя с учётом округления. Занятые байты не обязаны совпасть с более ранним CLI. Без карточки даже видимое окно не проходит новую приёмку. Содержимое дерева и значения показателя не отправляются в CI.
- `CPU_CARD`: тот же AT-SPI-наблюдатель у того же видимого PID нашёл отдельную карточку CPU. В доступном имени из видимых подписей проверены процент 0–100, интервал в мс, источник `/proc/stat` и время UTC в пределах запуска. Это не сравнение процентов между **разными** интервалами CLI и GUI.
- `ROOT_FS_CARD`: из видимых подписей карточки «Занято на /» по PID прочитаны **все три** величины, двоичные единицы, `statvfs(/)` и UTC. Каждая величина должна соответствовать независимым наблюдениям во время запуска окна с учётом округления. Не сравниваем с местом в более раннем CLI. Результат предыдущего стенда без этой карточки не проходит.
- `NET_IO_CARD`: в госте **только `lo`** — не добавляем NIC и не генерируем трафик ради проверки. В доступной подписи того же видимого PID нужны имя, пометка локальной петли, RX и TX в двоичных единицах за секунду, интервал, `/proc/net/dev` и UTC. Верхняя граница каждой скорости — из внешних счётчиков вокруг **этого** запуска окна с учётом округления. Это не измерение внешнего канала.
- `UPTIME_CARD`: из видимой строки «Время работы» панели «Среда» по PID прочитаны целые секунды (пары число/единица, всегда с секундами), источник `/proc/uptime` и UTC. Показанные секунды обязаны попасть в границы независимых чтений `/proc/uptime` во время **этого** запуска окна. Это не время до перезагрузки и не длительность сессии.
- `KERNEL_CARD`: из видимой строки «Ядро» панели «Среда» по PID прочитаны версия ядра (печатные ASCII без пробелов), источник `/proc/version` и UTC. Показанная версия обязана совпасть с независимым чтением `/proc/version` во время **этого** запуска окна — версия постоянна за загрузку. Это версия работающего ядра, не пакет kernel и не `VERSION_ID` os-release.
- `OS_VERSION_CARD`: из видимой строки «Версия системы» панели «Среда» по PID прочитаны либо версия (печатные ASCII, допустимы пробелы и скобки внутри, без кавычек), источник `/etc/os-release` и UTC, либо честное «нет данных». Если поле `VERSION` присутствует, показанное значение обязано совпасть с независимым чтением из `/etc/os-release` во время **этого** запуска окна — значение за загрузку не меняется. Если поле отсутствует (Arch-совместный образ без `VERSION`, как CachyOS Live), строка обязана показывать «Нет достоверного замера: /etc/os-release» — версия не выдумывается. Это человекочитаемая `VERSION`, не `VERSION_ID`, не `PRETTY_NAME` и не ядро.
- `HOSTNAME_CARD`: из видимой строки «Hostname» панели «Среда» по PID прочитаны имя узла (печатные ASCII, пробелы внутри допустимы, без краевых пробелов), источник `/proc/sys/kernel/hostname` и UTC. Показанное имя обязано попасть в границы независимых чтений `/proc/sys/kernel/hostname` во время **этого** запуска окна — имя могут сменить в работе, поэтому сверка по границам, а не по одному значению. Это имя ядра, не статика `/etc/hostname` и не DNS-имя.
- `UNCHANGED`: до/после совпали содержимое базы pacman, настройки pacman и зеркал, NetworkManager, networkd/resolved, ссылка и данные `/etc/resolv.conf`, адреса и маршруты IPv4/IPv6. Сравнение выполняется по возможности и после ошибки GUI. Это не утверждение о каждом байте ОС. Содержимое и хеши не покидают гостя.
- `PASS`: гостевой сценарий завершён. Таймаут, неполный отчёт и простое выключение VM — не успех.

## Воспроизведение

Нужен **одноразовый** x86-64 Linux-стенд с KVM, QEMU, GnuPG, xorriso, `xdotool`/libxdo, компилятором C, dev-пакетом AT-SPI и зависимостями сборки Tauri (см. `.github/workflows/cachyos-vm.yml`, Ubuntu 24.04). Гостю выделяется 5 ГиБ RAM. Запускать QEMU без root, не открывать `/dev/kvm` всем пользователям. Из корня:

```sh
cargo build --locked -p meshpilot-cli
npm --prefix apps/desktop ci
npm --prefix apps/desktop run tauri -- build --debug --no-bundle --ci -- --locked
media_dir="$(mktemp -d)"
profile=handheld-260628
bash tests/cachyos-vm/media.sh "$media_dir" "$profile"
source tests/cachyos-vm/fixtures.sh
select_fixture "$profile"
bash tests/cachyos-vm/run.sh "$media_dir/$name" target/debug/meshpilot apps/desktop/src-tauri/target/debug/meshpilot-desktop "$profile"
```

Для отрицательной проверки Desktop — `profile=260809`. Старый вызов скриптов без профиля по-прежнему означает 260809. Для архивного 251129 `run.sh` принимает только уже имеющуюся пару ISO и соседнюю `.sig`; отдельно проверить пару можно через `bash tests/cachyos-vm/verify.sh ПУТЬ_К_ISO 251129`. Носители не добавляются в Git или Dropbox.

На push изменений приложения/стенда workflow выбирает `handheld-260628`; после появления workflow в основной ветке ручной запуск также позволяет выбрать `260809`. Только документация не скачивает ISO. Локальные тесты правил выбора, проверки и вердикта: `python3 -m unittest discover -s tests/cachyos-vm`. Не запускать `guest.py` как диагностику реальной машины.
